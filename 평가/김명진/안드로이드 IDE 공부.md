# 안드로이드 개발 공부 노트

## 코틀린(Kotlin)과 자바(Java)의 관계

*   **JVM 언어**: 코틀린은 자바처럼 JVM(자바 가상 머신) 위에서 동작한다. 그래서 컴파일되면 자바 바이트코드로 변환된다.
*   **100% 호환성**: 코틀린 코드에서 자바 클래스를 가져와 쓸 수 있고, 반대로 자바 코드에서 코틀린 클래스를 쓸 수 있다. 한 프로젝트에 두 언어를 섞어 쓰는 것도 문제없다.
*   **더 간결하고 안전함**: 코틀린은 자바의 상용구 코드(boilerplate)를 많이 줄여준다. `val`, `var`, 데이터 클래스 등이 예시다. 특히 `?`를 이용한 Null 안정성 기능이 핵심. 컴파일 시점에 NullPointerException(NPE)을 방지할 수 있다.
*   **구글의 공식 언어**: 구글이 안드로이드 개발의 공식 언어로 코틀린을 지정했다 (Kotlin-first). 그래서 대부분의 새로운 라이브러리, 예제, 공식 문서가 코틀린 위주로 나온다.

## Android Studio 주요 파일 구분법

### 1. 매니페스트 파일 (AndroidManifest.xml)

*   **위치**: `app/src/main/AndroidManifest.xml`
*   **역할**: 앱의 '신분증' 같은 파일. 앱의 모든 구성요소를 여기에 등록해야 안드로이드 시스템이 인식할 수 있다.
*   **주요 내용**:
    *   **패키지 이름**: 앱의 고유 식별자.
    *   **컴포넌트 선언**: `Activity`, `Service`, `BroadcastReceiver` 등 모든 앱 구성요소를 `<activity>`, `<service>` 태그로 등록.
    *   **권한(Permissions)**: 인터넷, 카메라, 위치 정보 등 앱이 사용하려는 권한을 `<uses-permission>` 태그로 선언.
    *   **앱 아이콘, 이름 등**: 앱의 기본 정보를 설정.

### 2. 액티비티 파일 (예: MainActivity.kt)

*   **위치**: `app/src/main/java/내/패키지/이름/` 폴더 안. 파일 확장자가 `.kt` (코틀린) 또는 `.java` (자바)로 끝난다.
*   **역할**: 화면(UI) 하나에 대한 실제 동작과 로직을 코드로 작성하는 파일.
*   **주요 내용**:
    *   `onCreate()`: 액티비티가 생성될 때 실행되는 코드. 여기서 보통 XML 레이아웃을 화면에 연결(`setContentView`)하고, 버튼 클릭 리스너 등을 설정한다.
    *   버튼 클릭 시 어떤 동작을 할지, 데이터를 어디서 가져올지 등 모든 '기능'을 구현한다.

### 3. XML 레이아웃 파일 (예: activity_main.xml)

*   **위치**: `app/src/main/res/layout/` 폴더 안. 파일 확장자가 `.xml`로 끝난다.
*   **역할**: 화면의 '디자인'과 '구조'를 담당하는 파일.
*   **주요 내용**:
    *   `TextView`, `Button`, `ImageView` 등 화면에 보일 UI 요소(뷰)들을 태그 형태로 배치한다.
    *   각 뷰의 크기, 색상, 위치, 정렬 방식 등을 XML 속성으로 지정한다.
    *   액티비티 파일(.kt)에서 이 XML 파일을 가져와(`setContentView`) 화면에 보여주는 방식이다. 즉, `XML`은 뼈대와 디자인, `kt` 파일은 기능과 동작을 담당한다.
