# 품질관리 도구 정리

## 프로젝트 MVP

재난/전시 같은 상황에서는 인터넷이 끊길 수 있어서, “인터넷 없이도 구조 신호를 보내고 찾을 수 있는가”를 MVP 기준으로 잡았다. 사용자는 터치/사이드 버튼/음성으로 구조 신호를 보내고, 구조자는 레이더 UI나 BLE 연결로 위치를 찾는 흐름을 목표로 한다.

처음에는 ESLint랑 Prettier로 통일하려고 했다. 그런데 프로젝트가 모바일(Android)이고, 오프라인 환경에서 바로 돌려야 해서 Node.js 의존성을 붙이는 게 부담이었다. 그래서 Gradle 안에서 바로 도는 도구들로 방향을 바꿨다. 처음 써보는 것들이라 과하게 커스터마이즈하지 않고, 최소 설정으로 시작해보는 쪽을 택했다.

## 내가 고른 도구

- ktlint  
  Kotlin 스타일을 맞춰주는 포맷터/체커. Gradle 플러그인으로 붙여서 필요할 때 `ktlintCheck`/`ktlintFormat`을 돌렸다. 규칙은 기본값 위주로 시작했다.

- detekt  
  코드 스멜, 복잡도, 잠재 버그를 정적으로 잡아준다. `config/detekt/detekt.yml`로 기본 룰을 유지하면서 필요한 부분만 조정했다.

- EditorConfig  
  코드 스타일의 바닥선을 맞추는 용도다. `.editorconfig`에 기본 들여쓰기/개행 규칙을 넣어두고, ktlint가 그 기준을 따르게 했다.

## 프로젝트에서의 사용 방식

- 앱 모듈에서 ktlint/detekt 플러그인을 적용해, Gradle task로 필요할 때 돌리는 형태로 유지했다.  
- 오프라인에서도 바로 실행되는 도구만 남기고, Node 기반 툴은 이번에는 빼는 쪽으로 정리했다.  
- 처음이라서 과한 규칙 추가는 피하고, 기본 규칙부터 익숙해지도록 구성했다.
