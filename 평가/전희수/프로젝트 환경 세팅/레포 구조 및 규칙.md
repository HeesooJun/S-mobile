# 레포 구조와 개발 규칙 정리

지금 레포는 기본 구조 상태라서, 모바일 앱 특성상 복잡해지기 전에 MVVM 기준으로 정리하는 게 필요하다고 판단했다. UI와 로직을 분리해두면 유지보수나 테스트가 덜 부담스럽고, 팀원끼리 역할 나누기도 편하다. 그래서 아래 구조로 맞춰가야겠다고 정리했다.

## 폴더 구조(MVVM 기준, 적용 예정)

- presentation: 화면(UI), ViewModel, UI 상태
- domain: usecase, 비즈니스 로직, 모델
- data: API/로컬 데이터 소스, repository 구현
- di: 의존성 주입 모듈
- common/util: 공통 유틸

## 코딩 컨벤션

개발 경험이 적은 팀원도 있어서, 코드 품질과 일관성을 지키려면 규칙이 꼭 필요하다고 생각했다. 그래서 최소한의 규칙을 먼저 정하고, 도구로 자동화하는 방향으로 맞췄다.

- Kotlin 클래스/파일: PascalCase
- 함수/변수: camelCase
- 패키지: 소문자
- 리소스: snake_case
- 품질 관리 도구: ktlint + detekt + EditorConfig

## 브랜치 전략

충돌과 실수를 줄이기 위해 브랜치 흐름을 단순하게 가져가기로 했다. 작업은 develop에서 분기하고, 안정성은 main에서 보장하는 구조다.

- main: 항상 안정
- develop: 통합 브랜치
- feature/*, fix/*, chore/*: develop에서 분기
- PR은 develop으로, 머지 후 브랜치 삭제
