# UWB 메쉬 아이디어 정리

## 왜 메쉬로 가려는지

UWB로 연결 가능한 폰이 하나라도 있으면, 그 주변으로 망을 만들어 구조 신호 도달 범위를 넓히고 싶다. 단일 연결보다 “중계 노드”를 두면 신호가 끊길 확률을 줄일 수 있다고 봤다.

## 기본 가정

- 인터넷 없이 근거리 통신만 사용
- 일부 기기만 UWB 지원일 수 있음
- 재난 상황이라 연결 안정성이 낮고, 전력 제약이 큼

## 아이디어 흐름

- UWB 지원 기기가 허브 역할
- 주변 기기들은 BLE/Wi-Fi Direct로 허브와 연결
- 허브가 구조 신호를 수집/중계하고, 필요하면 다른 허브로 전달
- 구조자는 허브 기준으로 거리/방향(UWB) 정보를 받아 탐색

## 공부하면서 확인할 포인트

- UWB는 “거리 측정” 중심이라 데이터 전송은 BLE/Wi-Fi Direct가 더 적합함
- 다중 기기 UWB 세션 구성 방식(동시 연결 제한, 세션 수)
- 메시지 중복/폭주 방지(메시지 ID, TTL, hop count)
- 단순 flood vs 경량 라우팅(최소 규칙으로 유지)
- 전력 소모: 항상 광고/스캔 유지 시 배터리 부담 큼

## 당장 적용 가능한 최소 규칙(초안)

- 메시지 ID + TTL로 중복/폭주 억제
- hop count 제한(예: 2~3)
- 구조 신호는 짧게, 상태 정보는 간헐 전송

## 리스크/제약

- UWB 지원 기기 비율이 낮으면 허브가 부족할 수 있음
- 허브가 꺼지면 망이 붕괴될 수 있음
- 복잡한 라우팅은 MVP에 과함
