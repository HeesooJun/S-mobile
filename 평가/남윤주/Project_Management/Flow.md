# 일반적인 프로젝트의 흐름

개발 방법론 : Waterfall, Agile

기획 및 요구사항 분석 -> 설계 -> 개발 -> 테스트 -> 배포 -> 유지보수 및 운영

## 1. 기획 및 요구사항 분석

프로젝트의 목표를 설정하고 '무엇을 만들 것인가'를 정의

- 요구사항 명세
    - 구체적인 기능 목록
- 기술적 타당성 검토
    - 현재 기술 스택, 예산, 기간 내 구현 가능 여부 판단
- 일정 산정
    - 각 기능 구현 필요한 시간 예측, 마일 스톤 설정
- 기술 스택 선정


## 2. 설계
- 시스템 아키텍처 설계
    - 서버, 클라이언트, 데이터베이스, 외부 API 간 통신 구조를 짬
- DB 스키마 설계 (ERD)
    - 데이터를 어떻게 저장하고 연결할지 테이블 구조를 설계
- API 명세서 작성
    - 프론트엔드와 백엔드가 데이터를 주고 받을 규칙을 정의 (Swagger 활용)
- UI/UX 검토
    - Figma 등 화면 보며 컴포넌트 구조 구상

## 3. 개발
실제 코드를 작성하여 기능을 구현. 가장 긴 시간 소요

- 환경 설정
    - 개발 서버, 로컬 환경, 형상 관리 툴 등 세팅
- 프론트엔드/백엔드 개발
    - 프론트엔드: 화면 UI 구현, API 연동, 상태 관리
    - 백엔드: 비즈니스 로직 구현, DB 쿼리 작성, API 서버 구축 
- 단위 테스트 작성
    - 작성한 함수나 모듈이 의도대로 작동하는지 검증하는 테스트 코드 작성
- 코드 리뷰

## 4. 테스트
구현된 기능의 오류를 찾고 수정하는 단계
- 통합 테스트
    - 여러 모듈 합쳐졌을 때 데이터 흐름 정상적인지 확인
- 버그 수정
    - QA 팀, 내부 테스트 발견된 오류 수정
- 성능 테스트
    - 트래픽 몰릴 때 서버 부하 테스트
- 사용자 인수 테스트
    - 실제 사용 환경과 유사한 상태 최종 점검

## 5. 배포
완성된 소프트웨어 실제 사용자가 사용할 수 있는 환경(운영 서버)에 올림
- CI/CD 파이프라인 구축
    - CI: Continuous Integration 지속적 통합
    - CD: Continuous Deployment 지속적 배포
    - 빌드, 테스트, 배포 과정 자동화하여 효율성 높임 
- 클라우드 인프라 구성
    - AWS, GCP 등 서버 환경 구축하고 보안 설정
- 도메인 및 SSL 연결
    - 사용자가 접속할 주소 연결, 보안 인증서 적용
- 릴리즈

## 6. 유지 보수 및 운영
배포 후 안정적으로 서비스 운영하고 개선. 프로젝트의 끝이 아닌 서비스의 시작
- 모니터링
- 핫픽스
- 기능 개선 및 리팩토링
